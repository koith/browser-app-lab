# 화보 갤러리 개발·수집 운영 기준

이 문서는 **현재 운영 규칙**만 기술한다. 날짜별 작업 로그, 긴 CI 출력,
예전 버그 해결 과정은 여기나 [현재 원장 #605](https://github.com/koith/browser-app-lab/issues/605)에 누적하지 않는다.

## 개발 작업 흐름

1. **범위 결정:** 하나의 결함이나 실물 사진 부족분을 지정한다. `G-03`(밈미), `G-12`(심유이) 수집은 완료형 개발과 별도 관리한다.
2. **입력 확인:** 기존 보유 SHA 및 실제 화보 ID를 먼저 읽는다. 새 사진 여부를 URL 수나 다운로드 횟수로 추측하지 않는다.
3. **최소 수정:** 수집 입력→출처 판별→실파일 다운로드→디코드·중복·품질→저장 manifest→Pages에서 열람하는 **한 경로**를 바꾼다. 실패 경로는 별도 실험에서 검증하고 기존 안정 경로를 유지한다.
4. **PR 검증:** 변경된 Python/JS의 단위·회귀 검증을 먼저 실행한다. 실제 수집은 `main`의 명시적 수집 워크플로나 필요한 수집 작업에서만 실행한다. PR 테스트 성공을 신규 사진 수로 보고하지 않는다.
5. **반영·수용:** SHA 중복 제거 후 새 파일과 manifest를 원자적으로 반영하고, 정확한 Pages 배포에서 실제 JPEG 열람까지 확인한다.
6. **종료:** 신규 SHA와 이전→이후 사진 수가 증가했을 때만 해당 사진 보충 실적으로 세며, 전체 화보 완료는 공식 컷 수·원본 해상도·용량·광학 화질·워터마크까지 확인된 경우에만 인정한다. 0장이면 미완료 상태 유지.

## GitHub Actions 역할 분리

| 목적 | 조건 | 자동 실행 경계 |
| --- | --- | --- |
| 변경 코드 QA | 해당 코드나 테스트 파일의 PR 변경 | PR 단위. 실물 다운로드 불필요 |
| 실제 사진 수집 | 기존 `Gallery Full Missing Public Photos` 수집 워크플로 | 독립 실행과 제한된 배치, 수집 SHA 증가만 성과 |
| 갤러리 릴리스 QA | 배포 완료 후 실제 두 갤러리의 이미지·라이트박스 검사 | 운영 갤러리 통합 검사 유지 |
| **과거 사진 2·7·20장 등 특정 사건 QA** | 해당 테스트의 코드 변경 또는 운영자가 직접 수동 실행 | **모든 Pages 배포 시 자동 반복 금지** |
| 유한 개발 인계 | 현재 10/10 완료 상태 | 이슈/Pages 이벤트로 자동 실행 금지, 수동 및 변경 PR 테스트만 유지 |

GitHub의 `workflow_run`은 보조 워크플로를 실제로 새로 시작한다.
현재는 개별 과거 사진 사건 검사가 계속 재실행돼 비용과 대기열을 늘리므로
사건별 QA 4개와 완료된 인계 워크플로 1개의 자동 연쇄 실행을 중단한다.
**현재 운영 갤러리 통합 QA와 원본 수집은 중단하지 않는다.**

## 기록 보존과 원장 크기

- [원장 #605](https://github.com/koith/browser-app-lab/issues/605): 변경 시 **상태 표를 교체**하고 증거 링크를 덧붙여 표시만 수정한다. 새 실행 로그 전체 복사 금지.
- [기존 개발원장 79,196자 원본](./issue-605-original-body-2026-11-16.md): 보존용 읽기 전용 역사. 66개 기존 댓글도 그대로 보존.
- 대규모 `owner-index.json`, `stored-albums.json`, 이미지 SHA 목록은 **기능 데이터**이므로 임의 요약·삭제하지 않는다. 대화에는 **대상 작품의 전후 변경량과 실패 원인 요약**만 표시한다.
- PR 병합 후 임시 실험용 브랜치 및 동일 원인의 실패 자동 작업을 다시 늘리지 않는다. 다음 개선은 기존 워크플로 또는 테스트를 수정하여 해결한다.

## 실적 보고 한 줄 형식

`[모델/화보] 이전 고유컷 N → 신규 저장 M → 이후 고유컷 N+M, 파일 SHA/bytes, 배포 SHA, 브라우저 확인 PASS/FAIL/미검증`

사진이 0장 증가했다면 **0장**으로 적고, 검색 후보 수·PR 수·CI 성공 횟수를 수집 성과로 표시하지 않는다.

## AI 에이전트 문맥 제한 / 일감 완료 게이트

- 세션 시작 시 `apps/yui-gallery/` 또는 `apps/mimmi-gallery/`의 짧은 에이전트 안내와 이 문서, [원장 #605](https://github.com/koith/browser-app-lab/issues/605)의 **최신 본문만** 읽는다. 과거 댓글, 원장 원본, 전체 CI 로그, 대형 JSON 전문은 기본 입력으로 금지한다.
- 사진 보충 작업은 대상 모델과 실제 부족한 앨범 ID를 먼저 고르고, 해당 앨범의 물리적 저장 파일/SHA 및 공식 총수량을 기준선으로 잡는다. 완료 목표는 수집 후보가 아니라 **실제 추가·고화질 교체된 원본과 미완료 화보의 감소**다.
- 범위는 한 번에 검증 가능한 앨범 묶음으로 제한하고, 검증된 성공 경로를 다음 앨범에 재사용한다. 같은 403/502 경로를 반복 실행하지 말고 별도 정상 접근 가능한 출처/기존 사용자 보관 원본 등 합법적인 대안을 순서대로 검증한다.
- 완료의 순서: 실제 파일 다운로드 및 바이트/디코드/SHA/품질 검증 → 비파괴 인덱스 저장 → 실제 배포 확인 → 모바일 브라우저 표시 검증. 실패하면 열린 일감으로 남기고 다음 시도에 필요한 **짧은 실패 코드/재현 경로만** 기록한다.
- GitHub/도구 응답은 상태, 바뀐 파일명, 통과/실패 개수, 관련 링크만 대화에 노출한다. 대상 파일의 필요한 범위만 조회한다. 전문 출력·반복 요약으로 대화를 채우지 않는다.
- 사용자가 요청하지 않은 자동 정기 보고·자동 기능 개발을 재개하지 않는다. PR/문서/테스트 성공만으로 사진 확보나 실사용 검증 완료를 선언하지 않는다.
