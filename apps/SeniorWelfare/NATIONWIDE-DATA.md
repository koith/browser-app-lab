# SeniorWelfare 전국화 데이터 구조

## 목표
사용자 거주지역을 기준으로 `전국 공통 + 시도 + 시군구` 사업을 합쳐 같은 판정엔진으로 추천한다. 영등포구는 검증용 파일럿이며 서비스 범위를 영등포에 고정하지 않는다.

## 프로그램 필수 메타데이터
- `id`: 전역 고유 ID
- `scope.level`: `national | sido | sigungu`
- `scope.codes`: 적용 행정구역 코드 배열. 전국은 빈 배열
- `source_urls`: 공식 원문 URL 배열
- `checked_at`: 마지막 온라인 검증일
- `effective_from`, `effective_to`: 시행기간. 모르면 null
- `conf`: `verified | partial`
- 기존 `rules`: 개인 자격 판정 규칙

## 런타임 합성
1. 국가 공통 프로그램 로드
2. 선택한 시도 코드에 맞는 프로그램 추가
3. 선택한 시군구 코드에 맞는 프로그램 추가
4. 동일 ID 중복 제거
5. 개인 프로필 rules 판정
6. `effective_*`와 `checked_at`으로 만료/노후 데이터 경고

## 검증 원칙
정부·지자체·공공기관·실제 수행기관의 공식 온라인 자료를 우선한다. 검색 결과나 블로그만으로 verified 처리하지 않는다. 공개자료에서 핵심 조건을 확인할 수 없는 세부사항만 partial로 둔다. 폐지된 사업은 추천에서 제거한다.

## 확장 순서
1. 기존 영등포 44개를 national / 서울 / 영등포로 분리
2. 국가 공통 사업을 지역 데이터와 분리
3. 서울시 공통 사업 분리
4. 영등포구 로컬 사업 분리
5. 지역 선택 UI와 3계층 loader 연결
6. 타 시군구는 데이터 파일만 추가하면 동작하도록 유지

`regions.json`은 지역 레지스트리다. 현재 영등포만 verified 파일럿이며 나머지 시도는 planned 상태로 명시해, 데이터가 없는 지역을 지원하는 것처럼 표시하지 않는다.
