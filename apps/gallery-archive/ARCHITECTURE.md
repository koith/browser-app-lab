# 화보 갤러리 운영 설계 — P0 안정화 및 무료 운영

## 목적과 전제

- 기존 **TeraBox는 원본 보관소**로 유지하며 삭제·덮어쓰기하지 않는다.
- **Cloudflare R2 Standard는 비공개 읽기용 영속 사본**이다. 도입 전까지 현재 경로가 그대로 동작한다.
- **GitHub Pages는 화면과 이미 공개 저장된 SHA 검증 사진**만 배포한다. 사적인 R2 객체나 서명 URL은 Pages에 공개하지 않는다.
- **Render 무료 웹 서버**가 R2에서 사본을 인증된 요청으로 읽고 SHA-256·바이트 수를 검증한 뒤 기존 갤러리 API로 출력한다.
- 수집·저장·표시를 하나의 동작으로 간주하지 않는다. 실제 파일 저장과 표시까지 통과한 사진만 확보 완료로 집계한다.

## 일반적인 서비스 구성

```text
게시처 및 기존 보관 자료 → 수집 작업(전수 후보·중복 검증)
                              │
                              ▼
            작업 큐 → SHA-256·크기·픽셀 디코딩 검증
                              │
                ┌─────────────┴────────────────┐
                ▼                              ▼
       기존 TeraBox 원본 유지          비공개 R2 Standard 사본
                                               │
                                  Render 읽기 전용 게이트웨이
                                  (SHA/크기 검증·짧은 RAM 캐시)
                                               │
        GitHub Pages — 로컬 공개 저장본 우선 → 지연 로딩 썸네일/원본뷰어
```

## 읽기 및 복구 정책

1. 물리적으로 Pages에 저장된 **동일 SHA 사진**은 Render 호출 없이 우선 표시한다.
2. 저장된 사본이 없는 사진은 기존 모델별 인증된 게이트웨이를 통해 **비공개 R2 사본을 우선 조회**한다.
3. R2 사본이 아직 없으면 **동일한 모델의 TeraBox 원본**을 기존 방식으로 확인한다. 모델 간 계정 혼용 금지.
4. 모든 반환 파일은 원본 목록의 SHA-256과 바이트 수를 검증한다. 불일치 파일은 **절대 표시·저장 성공 처리하지 않는다**.
5. 화면은 보이는 사진만 로딩한다. 실패한 타일만 최대 3회·45초 대기·동시 2개 이하로 재시도한다. 전체 214장 상태를 재시도 조건으로 삼지 않는다.
6. Render 재시작 후 RAM 캐시는 비어 있어도 **R2에 저장된 파일은 다시 읽혀야 한다**. RAM 캐시나 TeraBox 세션만으로 영속성 통과를 판정하지 않는다.

## 수집·저장 원칙

- 전수 수집 대상은 기존 미확보 목록을 우선한다. 단, **라이브 표시 장애(P0)가 있으면 먼저 복구**한다.
- 후보 발견 → 실제 파일 바이트 수령 → SHA·픽셀 검사 → 개인 보관소에 불변 저장 → 원격 재읽기 → 갤러리 색인 반영 → 브라우저 표시 검사의 순서다.
- 전체 사진이 실제 저장됐다는 증거가 없는 사진을 '확보 완료'로 표기하지 않는다.
- 업로드는 불변(immutable)으로, 재실행 시 목적지의 동일 SHA를 확인하고 건너뛴다. 다른 SHA 파일은 덮어쓰지 않는다.
- 사본 전체의 재읽기를 통과하기 전에는 현재 사용 중인 보관 목록을 새 목록으로 교체하지 않는다. 실패 시 마지막 정상 목록을 유지한다.
- 기존 미확보 사진까지 합쳐도 저장 상한을 사전 검사하고, 초과 시 유료로 확장하지 않고 안전하게 중단한다.

## 무료 운영 보호 장치

- 공식 R2 Standard 월 기본 무료량은 **10GB-month**, Class A **100만**, Class B **1,000만** 요청이다. 기본 무료량은 계정 전체 사용량에 적용된다.
- 갤러리용 프로젝트의 별도 보수적 상한은 **8,000,000,000 bytes** 및 이미지 **25,000개**, 예상 쓰기 100,000 / 읽기 500,000으로 둔다.
- 실제 이전 전 Cloudflare API로 **Standard 저장 등급**, r2.dev 비활성화, 공개 사용자 도메인 비활성화를 확인한다.
- 실제 클라우드 계정의 기존 사용량까지 자동 확인하지 못하면 **절대 무과금이라고 가정하지 않는다**. 계정 사용자 승인과 비용 보호 설정 확인을 선행한다.
- R2 키는 GitHub Actions의 승인된 비밀값 또는 Render 서버 환경변수에만 저장하고 브라우저·화보 페이지에 전달하지 않는다.
- 마이그레이션은 별도 명시적 실행 시에만 진행한다. 기존 배포가 새 R2를 자동 활성화하거나 무단 업로드하지 않는다.

## 배포 승인 게이트

- 브랜치 → PR → 회귀검사 → 병합 → Pages/Render 정확한 SHA 배포 → **실제 배포 서비스 QA** 순서를 반드시 유지한다.
- 두 모델의 실제 원본 **HTTP 200 + SHA + 이미지 디코딩**, 저장 파일 우선 사용, 갤러리 입장·스크롤·전체화면·새로고침·뒤로가기를 Chromium과 WebKit에서 검사한다.
- **배포 직후뿐 아니라 Render 재시작·유휴복귀 시에도** 실원본을 확인한다.
- 사본에 저장되지 않은 사진과 카탈로그 실패를 별도 통계로 기록한다. 일부 사진만 성공한 것을 전체 정상으로 보고하지 않는다.
- 실패 시 이미 검증된 화면·TeraBox 원본·기존 저장본을 유지한다. R2 사용을 기본 비활성화하면 기존 경로로 되돌릴 수 있도록 한다.

**완료 조건:** 두 갤러리 실제 열람과 원본·미리보기가 정상이며, 유휴복귀에도 유지되고, 미확보 수집 파이프라인의 신규 1건 이상이 실제 저장부터 화면 표시까지 재검증된다. 이 조건 전까지 '완료'로 표기하지 않는다.
