## 일감 처리
- **작업 한 건 = 구체적 목표 + 확인 가능한 완료 조건 + PR.** 서로 독립적인 큰 목표는 GitHub sub-issue로 쪼개고 #607에 링크만 건다.
- 순서: 최신 main/Render 실제 상태 → 최소 관련 코드 조회 → 수정 → 오프라인 테스트 → 브라우저 QA → 병합 → 실제 배포 확인 → 원격 자료/픽셀·동작 확인 → 체크 갱신.
- 데이터가 미확보되거나 접근할 수 없으면 **FAILED/UNVERIFIED**로 남긴다. GitHub CI 성공이나 작업 접수는 원본 저장 성공이 아니다.
- 코드를 여러 곳에 같은 방식으로 복제하지 않는다. 안전한 공통 모듈·작은 PR·실패 회귀 테스트를 우선하며, 배포/데이터 정합성 같은 경계는 별도 검증한다.
- 실패하면 동일 호출 반복보다 실패 경로·로그 범위·원인별 대체 경로를 조사하고 한 번에 수정한다.
- GitHub Actions 상태 보고는 **반복 댓글 POST 금지**, 이미 있는 봇 댓글 한 건만 PATCH. 개인 정보를 공개 로그에 적지 않는다.
- 교집합 관련 새 대화는 원장 원문/모든 댓글/전체 로그를 통째로 읽지 않고 #607 핵심 10개, 최근 PR/Actions 및 해당 소스 파일만 확인한다.
