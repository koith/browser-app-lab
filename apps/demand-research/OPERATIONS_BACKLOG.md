# 교집합 — 보조 일감 및 검증 기준 (간결본)

**정본:** [GitHub Issue #607](https://github.com/koith/browser-app-lab/issues/607)의 **INT-01~INT-10** 체크박스만 핵심 완료 판정에 사용한다. 여기서 10개 항목의 진행 상태를 다시 적지 않는다. 반복 실행 상태는 이슈에 갱신되는 단일 자동 진행판에서 확인한다.

**과거 기록 (읽기 전용 보존):** [기존 보조 원장 원문](history/OPERATIONS_BACKLOG_full_2026-11-16.md) · [기존 Issue #607 본문 원문](history/issue-607-original-2026-11-16.md) · 기존 이슈 댓글 71개.

## 별도 작업 — 최종 운영 검증은 미완료

| ID | 작업 목표 | 상태 | 판정에 필요한 증거 |
|---|---|---|---|
| INT-11 | 지정 공개 계정의 프로필·헤더·소개·공개 게시글/답글/미디어·댓글·공개 관계 목록을 보존하고 출처별 SNS형 화면에서 조회 | **UNVERIFIED** | 계정별 원본/첨부 누락 목록, 원격 SHA-256 재읽기, 실제 UI 검증. 접근할 수 없는 원본은 따로 표시 |
| INT-12 | 실시간 피드의 광고·수동 계정 차단·금지 문구 필터가 모든 SNS와 캐시 경로에 동일 적용 | **CODE/배포 검증 이력, 실사용 전수는 미완료** | 웹/모바일 실데이터, 광고 누락 재현, 단어 ‘야단라’ 변형·재로드·오프라인 캐시 테스트 |
| INT-13 | 공개 영상 트렌드·활동량·출처별 통계를 실제 데이터로 검증하고 원본 보존과 연결 | **UNVERIFIED** | 2개 이상 시점의 수치 비교, 출처·페이지·영상과 원본 연결, 실데이터 목록 일치 |

## 현재 제품 품질 게이트

- **백업 완전성:** 접수 ≠ 암호화 ZIP 저장 ≠ 미디어 전수 SHA 검증 ≠ 원래 SNS의 게시물 전수 확보. 단계별 증거를 구별한다. 기존 스냅샷은 불변으로 유지한다.
- **SNS 화면 충실도:** Bluesky/Mastodon의 실제 공개 계정과 동일 계정 보관 화면을 동일 뷰포트/시점에서 비교한다. RGB 100% 일치 및 두 서비스 모두 검증 전에는 **PIXEL_IDENTICAL이라고 기록하지 않는다**. [실측 검사](https://github.com/koith/browser-app-lab/actions/workflows/intersection-visual-parity.yml).
- **실시간 제외:** 지정한 문구 ‘야단라’ 포함 게시글은 라이브 집계와 파생 통계에서 제외하되, 이미 승인된 원본 보관물을 임의 삭제하지 않는다.
- **인증과 접근:** 소유자 전용 기록은 공개 이슈/Actions 로그에 게시하지 않는다. 접근 불가능한 게시글·DM 등을 가져왔다고 표시하지 않는다.

## 작업 처리 규칙

새 실개발 작업은 독립된 GitHub Issue/PR에서 코드 변경 → 테스트 → 배포 → 운영 검증 → 해당 작업 상태 변경 순서로 다룬다. 하나의 이슈 댓글에 작업 로그를 계속 붙이지 않는다. 반복 상태는 고정 댓글 **1개를 갱신**하고, 상세 증빙은 해당 PR·Actions 실행 링크로 남긴다. 병합·합성 CI만으로 핵심 일감을 완료 처리하지 않는다.

새 날짜별 로그를 이 파일에 덧붙이지 않는다. 기록 복원이 필요하면 위의 보존 스냅샷 또는 Git 이력/Actions 실행 원본을 사용한다. 문서 목표는 **5,000자 이내**다.
