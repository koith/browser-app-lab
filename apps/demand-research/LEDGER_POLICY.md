# 교집합 개발원장 경량 관리 규칙

최신 상태의 **단일 원장**은 [Issue #607](https://github.com/koith/browser-app-lab/issues/607) 본문 P0/P1/P2 상위 10개 과제다. 이 규칙을 적용해 2026-11-16부터 장문의 일별 보고를 본문 끝에 쌓지 않는다.

- **#607 본문 최대 권장 5,000자**. 상위 일감 코드(INT-01~10), 체크 상태, 완료 조건, 최신 증거 링크만 수정한다. 체크를 [x]로 바꾸려면 원격 원본 SHA 재읽기/운영 브라우저 검증 등 해당 과제의 실제 완료 증거가 있어야 한다. 합성 CI 통과는 상위 완료가 아니다.
- **자동 운영판은 댓글 단 1개** (기존 bot 댓글 ID `6619616433`)를 덮어쓴다. 5,000자를 넘으면 자동 게시를 거절한다. 게시판에 포함된 완료 개수는 'P0/P1/P2 본문 상위 10건'에서만 계산한다. 최신 실행 최대 3개만 요약하고 운영 상태를 미검증으로 표시할 수 있다.
- **개발 상세/실행 근거는 PR·Actions 실행 URL**에 둔다. 변경마다 Issue 본문/댓글/별도 Markdown에 동일한 로그를 중복 복사하지 않는다. 진행 보고에서 현재 작업·완료·미완료를 분리하고 체크 수를 부풀리지 않는다.
- **과거 기록은 보존**. #607 이전 장문 원본은 [원문 보존 파일](history/issue-607-original-2026-11-16.md), 기존 71개 댓글과 과거 [OPERATIONS_BACKLOG.md](OPERATIONS_BACKLOG.md)는 역사 자료. 삭제·덮어쓰지 않는다. 새 회차용 대형 JSON 이벤트 덤프/무한 누적 표를 만들지 않는다.
- 자동화·에이전트는 Issue 본문 수정 시 상위 10건만 선택적으로 갱신하며 별도 본문 섹션을 자동 추가하지 않는다. 매 실행마다 대형 과거 기록을 불러오지 말고 최신 Issue 본문·단일 자동 댓글과 관련 PR/Actions 증거만 좁게 읽는다.
- **검증**: 원장 본문 길이 5,000자 이내, 자동 댓글 5,000자 이내, 최상위 체크 10개 고유, 현재 완료 개수와 체크 개수 동일. 기준 위반은 새 기록을 보태서 우회하지 않고 기록 구조부터 수정한다.
