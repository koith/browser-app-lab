# 교집합 — 최소 컨텍스트 작업 지침

대상: `apps/demand-research/`, 관련 `intersection-*`·`demand-*` 워크플로.
목적: 프로젝트 전체 이력/로그를 대화에 다시 싣지 않고 **실개발→테스트→배포→운영 검증**을 계속한다.

## 세션 시작 시 필요한 정보
1. 이 파일 및 [LEDGER_POLICY.md](LEDGER_POLICY.md) (두 파일 합계 4KB 이내).
2. [Issue #607](https://github.com/koith/browser-app-lab/issues/607)의 **현재 본문만** 읽고 P0 중 가장 먼저 해결 가능한 과제 선택. 댓글 71개나 원장 보존본은 읽지 않는다.
3. 해당 과제에 필요한 코드 파일과 실패 로그의 **관련 부분만** 조회. 파일명/함수명을 찾고 필요한 줄 범위를 선택한다.
4. 마지막으로 바뀐 커밋/PR을 직접 확인하고 이전 대화에서 했다는 보고만으로 완료 처리하지 않는다.

## 대화 부피 제한
- 처음부터 README 전문(약 29KB), `index.html` 전문(약 190KB), 과거 원장, 100개 이상의 테스트 파일, GitHub Actions 전체 로그, 다른 앱의 이력을 불러오지 않는다.
- 도구 결과는 **필요한 사실·오류 주변 15줄·커밋/URL** 위주로 출력하며 기본 목표 **호출당 2,000자 이내**. 다량의 데이터는 코드 내부에서 요약하고 원문을 채팅에 복사하지 않는다.
- 전체 파일 쓰기가 필요할 때는 도구 내부에서 읽어 변경하고, 채팅에는 변경 범위·검증만 표시한다.
- 같은 긴 결과를 다시 출력하거나, 날짜별 진행 보고를 #607/대화에 누적하지 않는다.
- 이전 대화 전체를 요약하라고 요청하지 않는다. 교집합 과제와 무관한 다른 앱 이력/개인 맥락은 끌어오지 않는다.

## 완료 판정 및 인수인계
- 병합/CI 통과만으로 원본 확보·저장 성공·픽셀 동일 판정 금지. 실사용 자료·원격 원본 재읽기·배포 상태 등 해당 작업의 수락 기준을 확인한다.
- 종료 보고는 **이번 완료 건수 / 핵심 미완료 건수 / 검증된 증거 링크 / 막힌 원인 / 다음 조치**를 짧게 명시한다.
- ChatGPT의 '대화 최대 길이' 경고 자체는 저장소 수정으로 해결됐다고 주장하지 않는다. 이 지침은 토큰 낭비 예방책이며 앱/서버 오류는 별도다.
