# 밈미(MIMMI) 갤러리 개발 인수인계서 — 2026-10-29

## 1. 사용자 확정 요구

- 심유이 갤러리 **최신 모바일 표시 방식**을 밈미에도 동일하게 적용한다. 참고 화면: 2026-10-29 사용자 제공 iPhone Safari YUI v0.1.0-beta.19 스크린샷.
- 어두운 배경, 상단 `MIMMI GALLERY` 로고·검색·버전, **상단 왼쪽 이미지 장수 / 오른쪽 화보 수**, `화보 ⇄` 발행처 전환, 2열 표지 카드, 출처·화보별 실제 장수·하단 제목 오버레이, 사진 상세/전체화면·좌우 이동을 유지한다.
- 심유이 버튼은 **새 탭**으로 열고 심유이 개발 작업을 건드리지 않는다.
- **실제 파일이 저장되고 갤러리에서 제공되는 사진만** 장수/화보 수에 반영한다. 링크를 찾았거나 HTTP SHA만 검증한 미저장 사진은 수량으로 표시하지 않는다.
- 화보당 10장 제한은 잘못된 설계다. 공개적으로 볼 수 있는 전체 페이지·정상 스크롤·다른 출처를 병행한다. 특정 사이트가 10장만 보여줘도 완결로 처리하지 않는다.
- 유료 브라우저 서비스/TinyFish 충전/테라박스에 의존하지 않는다. GitHub Actions, Python requests/BeautifulSoup/Pillow, 무료 Playwright Chromium/WebKit을 사용한다.
- 저작권·접근권한은 구별한다. 공개 접근 가능하다고 자동으로 재배포 권한이 생기는 것은 아니다. 현재 Pages 사진은 **공개 배포**다. 허가 없는 상업 유료 원본·로그인/결제 우회·비공개 리소스 수집은 금지한다.

## 2. 저장소·배포·현황

- Repo: https://github.com/koith/browser-app-lab
- 밈미 UI: https://koith.github.io/browser-app-lab/apps/mimmi-gallery/
- 심유이 UI: https://koith.github.io/browser-app-lab/apps/yui-gallery/
- 주요 디렉터리: `apps/mimmi-gallery/`; 심유이 `apps/yui-gallery/`는 독립 유지.
- `apps/mimmi-gallery/stored-albums.json`은 **실제 저장 사진의 단일 출처**. `physical_verified_image_count`와 `albums[].images[]`를 합산 검증한다.
- `apps/mimmi-gallery/stored-albums/<album-id>/<sha256>.<ext>`에 물리적 사진 파일이 있어야 한다. 각 파일의 byte length, SHA-256을 다시 계산한다.
- 2026-10-29 확인 기준: **849개 실제 파일 / 35개 화보 / 약 303MiB**. 이 숫자는 스냅샷이다. 이후 정확한 수량은 `stored-albums.json` 및 배포된 UI에서 재확인한다.
- 2026-10-29 추가 공개 출처 CreamSoda/Xiutu에서 **6개 화보 / 373개 URL의 실제 HTTP 이미지 SHA 검증** 성공. **저장된 파일 수에 포함하지 않는다**. `xiutu-public-previews.json` 참조.
- 실제 게시물의 전체 장수와 저장 장수는 다르다. 모든 화보는 발행사 완전판으로 표시하지 않는다.

## 3. 심유이 UI와 동기화

- 참조: `apps/yui-gallery/index.html` (YUI v0.1.0-beta.19 계열).
- 밈미: `apps/mimmi-gallery/index.html`. 2026-10-29 기준 **이미** 모바일 베타.19 형태의 컴팩트 레이아웃 CSS(`Match the latest YUI beta.19`), `.browse-meta`, `#inventory`, `#total`, `.grid` 모바일 2열, `.cover-labels`, `.album-count`, `.edition-sticker`, `#browse-toggle`가 적용되어 있다.
- `#inventory`는 `stored`의 실제 이미지 길이를 더한 `<n>장 · 실제 저장본`을 표시한다. `#total`은 실제 화보 수만 보여준다. **심유이 화면의 '미리보기 13장'이라는 수치를 밈미에 하드코딩하지 않는다.** 밈미에서는 미저장 연구 미리보기를 노출하지 않기 때문이다.
- 헤더에서 심유이 링크는 `../yui-gallery/` `target="_blank"` `rel="noopener noreferrer"`.
- `gallery-labels.js`, `publishers.js`, `album-covers.json`, `album-aliases.json`, `identity-exclusions.json`은 카드 표기/제외/표지 정책에 영향이 있으므로 검수한다.
- 최신 심유이 CSS 변경을 복제할 때 밈미 전용 모델 전환, 저장본-only 카운터, 저장 경로 검증은 유지한다.

## 4. 수집 → 검증 → 저장 → 배포

1. **수집**: `collect_pixibb_public.py`, `discover_v2ph_actor.py`, `collect_xiutu_public.py` 등으로 공개 HTML의 실제 사진 주소를 찾는다. V2PH는 화보당 180장/35페이지 제한과 8개 작품 단위 회전 배치를 지원하며 Playwright 정상 스크롤을 병행한다.
2. **검증**: 원본 공개 이미지 URL에서 바이트를 읽고 Pillow로 포맷/크기를 확인하며 SHA-256·byte count를 기록한다. 이 단계는 아카이빙이 **아니다**.
3. **소스 합치기**: `build_model_gallery.py`가 출처별 검증 자료를 `source-viewer-albums.json`에 합친다. SHA가 같은 사진의 다른 URL은 `alternate_source_urls`로 보존한다.
4. **실제 저장**: `publish_stored_public.py`가 공개 재게시 권한을 확인한 사진을 내려받고 정확한 SHA/byte length를 재검증해 `stored-albums/`에 기록한다. 원래 URL 실패 시 SHA가 같은 것으로 이미 검증된 대체 URL만 시도한다.
5. **배포**: `.github/workflows/mimmi-stored-public-gallery.yml`이 사진 파일+index를 커밋하고 Chromium/WebKit 모바일 QA 후 GitHub Pages에서 표시한다.
6. **검수**: `test_mobile_album.cjs`, `test_webkit_photo.cjs`는 실제 파일 존재/해시와 사진 표시를 검사한다. GitHub Actions 성공, `main` SHA, Pages 배포, Safari 실기기 순서로 확인한다.

## 5. 무료 GitHub Actions

- `.github/workflows/mimmi-v2ph-actor-expansion.yml`: V2PH 다중 페이지 및 브라우저 스크롤.
- `.github/workflows/mimmi-xiutu-cream-soda-public.yml`: CreamSoda 대체 공개 페이지 수집 및 개별 HTTP SHA.
- `.github/workflows/mimmi-stored-public-gallery.yml`: 저장·검증·커밋·모바일 QA. 1회 2패스 × 최대 50MiB, GitHub Pages 저장 공간 상한 780MiB.
- `.github/workflows/mimmi-gallery-smoke.yml`: Mimmi UI/수집 회귀 테스트.
- `workflow_run` 자동 실행은 앞선 작업이 성공해도 저장 작업이 큐에서 지연되거나 취소될 수 있다. **완료 여부는 저장된 `main` index와 물리적 파일로만 판정**한다.
- GitHub Actions UI에서 수동 `Run workflow`로 재시도 가능. 동시에 여러 자동화가 `main`을 갱신할 수 있으므로 커밋 충돌을 주의한다.

## 6. 바로 이어서 할 일 (미완료)

1. **373개 검증 사진을 실제 저장**: 작업 브랜치 `feat/mimmi-free-xiutu-373-real-files-first-20261029`에 `publish_stored_public.py` 수정과 `test_xiutu_physical_store.py`가 커밋돼 있으나, **테스트/PR/병합/실제 저장은 아직 미완료**다. 먼저 테스트 실행과 저작권·재게시 권한을 확인하고 PR→병합→저장→해시·UI 검증을 진행한다.
2. Xiutu의 6개 화보 중 기존 V2PH 10장 화보와 같은 판본인 경우 동일 ID에 합친다. 제목만 비슷한 다른 판본은 섞지 말고 표지·발행처·세트명·실제 SHA를 비교한다.
3. 사진 10장뿐인 기존 V2PH 앨범은 추가 공개 출처와 대조하고, 페이지/스크롤 후에도 없으면 `미완료`로 기록한다.
4. GitHub Pages 저장 예산 780MiB 및 리포지토리 용량·저작권을 점검한다. 더 많은 원본의 **비공개 보관**이 필요하면 Pages 공개 저장을 비공개 아카이브와 혼동하지 말고 별도 적법한 방식을 설계한다.
5. iPhone Safari 실제 화면을 YUI 베타.19 스크린샷과 대조하고 표지 2열, 카드 출처/사진 수, 검색, 상세, 좌우 넘김, 새 탭 전환을 확인한다. 브라우저 검수는 무료 Playwright가 기본이며 TinyFish 결제는 필요 없다.
6. 작업 완료 보고는 `실제 저장 파일 수 / 실제 화보 수 / 새로 저장한 파일 수 / PR / main SHA / Actions 결과 / Pages 배포`를 구분해 제공한다.
